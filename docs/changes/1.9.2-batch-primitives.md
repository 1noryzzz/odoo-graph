# 1.9.2 — Batch Primitives

## What changed

- `field` accepts 2–50 targets and returns a `field_batch` envelope.
- `overrides` accepts 2–50 targets and returns an `overrides_batch` envelope.
- A batch loads the graph once, preserves input order, and isolates missing
  symbols from valid results.
- Found items embed the complete existing single-target payload. Missing items
  include conservative suggestions where available.
- Batch telemetry records comma-joined targets plus semantic result and
  requested/found/missing counts.

## Usage

Query several fields with one graph load:

```bash
odoo-graph field \
  model.a.field_x \
  model.a.field_y \
  model.b.field_x \
  --db target_db
```

Query several override chains:

```bash
odoo-graph overrides \
  model.a.action_confirm \
  model.b.action_confirm \
  --db target_db
```

## Compatibility

- A one-target `field` or `overrides` invocation keeps its existing human and
  JSON payload.
- Batch envelopes are used only for two or more targets.
- Partial batches exit `0`; all-missing batches exit non-zero.
- Telemetry continues to use `success_non_empty` for usable partial output.
- More than 50 targets returns a usage error before graph loading.

## Intentionally excluded

This release does not add a workflow DSL, heterogeneous inspection command,
automatic symbol discovery, persistent graph cache, method-body analysis, or
signature and `super()` correctness checks.
