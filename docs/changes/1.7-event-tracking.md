# Release Notes: 1.7.0

1.7.0 adds local telemetry for `odoo-graph` CLI usage. The goal is to make agent-driven workflows easier to improve by recording how often commands are chained, retried, expanded, or used in fan-out patterns.

## Highlights

- Added local SQLite telemetry for business CLI commands.
- Added `odoo-graph telemetry init` for explicit telemetry DB initialization.
- Added `odoo-graph telemetry report` to run post-processing and analysis in one command.
- Added report coverage for session call counts, command frequency, follow-up, retry, expansion, path fan-out, batch model / field exploration, load overhead, and 30s / 60s / 120s gap sensitivity.
- Updated README, usage guide, architecture notes, roadmap, and the runtime-probe skill with telemetry usage guidance.

## Usage

```bash
odoo-graph telemetry init
odoo-graph telemetry report
odoo-graph telemetry report -f json
```

Telemetry is local-only and defaults to:

```text
~/.cache/odoo-graph/telemetry.sqlite3
```

Use `ODOO_GRAPH_TELEMETRY_DB` to override the DB path. Use `--no-telemetry` for one invocation or `ODOO_GRAPH_TELEMETRY=0` to disable collection.

## Compatibility

- Package version is now `1.7.0`.
- Python requirement remains `>=3.10`.
- `--help`, `--version`, root action, and shell-level startup failures are not part of the formal telemetry statistics.
