# 1.9.1 — Robustness

## What changed

- `context` now keeps valid models when part of an explicit group is missing.
  Structured output includes `result`, `selected_models`, and `missing_models`;
  each missing model has at most three conservative suggestions.
- Partial `context` results exit successfully and retain the existing telemetry
  top-level status. `result_summary_json` records requested, resolved, and
  missing counts plus the semantic result.
- `dump --odoo-path` is now optional. Without a CLI value or `ODOO_PATH`,
  `odoo-graph` checks `.`, `./odoo`, `./odoo-17.0`, `../odoo`, then
  `../odoo-17.0` for `odoo-bin`.
- Invalid explicit paths no longer silently fall back. Diagnostics list the
  fixed candidate set and print a corrected command when one is available.
- `meta.json` now records `generated_at`, `cwd`, and `package_version` in
  addition to the existing database, source path, addon, summary, and resolve
  metadata.

## Usage

Let the CLI discover a common repository layout:

```bash
odoo-graph dump -c odoo.conf -d target_db
```

Override discovery only when necessary:

```bash
odoo-graph dump -c odoo.conf -d target_db --odoo-path /path/to/odoo
```

Use all valid evidence from a mixed model group:

```bash
odoo-graph context model.a mistyped.model model.b --db target_db -f json
```

## Compatibility

- Existing query semantics are unchanged.
- `context` returns `0` for `success` and `partial`, and non-zero for
  `not_found`.
- Telemetry still uses `success_non_empty` for usable partial output; no new
  top-level `partial` status is introduced.
- Normal query output does not include cache provenance.

## Intentionally excluded

This release does not reject stale caches, recursively scan for Odoo source,
add persistent graph caching, add registry snapshot diffing, or implement the
1.9.2 batch `field` / `overrides` commands.
