# 技术改进记录：`_inherits` 委托字段诊断

## 状态

- 状态：已实现
- 类型：查询/诊断能力增强
- 影响范围：`field` / `model` 查询、human/json 输出、AI runtime-probe skill、README 使用说明
- 验证数据：`registry-probe/local_out`

## 背景

在一次 Odoo 字段排查中，曾出现过典型误判：链式 `_inherits` 委托继承下，某个字段不在子模型自己的 SQL 表里，但它已经通过 Odoo registry 进入子模型的 `_fields`，并且可能因为 `inverse=_inverse_related` 可以通过子模型 `write()` 更新。

错误的判断路径通常是：

```text
子模型 SQL 表中没有该列 -> 该字段不属于子模型 -> 子模型 write() 不能更新
```

但在 `_inherits` 场景下，更可靠的判断路径应该是：

```text
env.registry / model._fields -> related/depends 链 -> _inherits 委托链 -> inverse/readonly 可写性
```

## 真实案例

字段：

```text
ifs.gar.entry.supplier.vat
```

最终字段路径：

```text
ifs.gar.entry.supplier.vat
 -> ifs.gar.invite.supplier.vat
 -> ifs.base.company.vat
 -> res.company.vat
 -> res.partner.vat
```

`_inherits` 委托链：

```text
ifs.gar.entry.supplier --invite_id--> ifs.gar.invite.supplier
ifs.gar.invite.supplier --ifs_company_id--> ifs.base.company
ifs.base.company --company_id--> res.company
```

关键结论：

- `ifs.gar.entry.supplier.vat` 不是当前模型直接声明的本地字段。
- 它是 delegated related field。
- 当前模型 SQL 表没有同名列，并不等于 ORM 不可写。
- 最终有效来源字段是 `res.partner.vat`。
- 当前字段可写，原因是 delegated related 字段带 `inverse=_inverse_related`。

## 改进目标

`odoo-graph field <model.field>` 应直接回答这些问题：

1. 字段是当前模型本地声明的，还是 related/computed/delegated 字段？
2. 如果来自 `_inherits`，完整委托链是什么？
3. 最终有效来源字段是什么？
4. 当前模型能否通过 ORM 写入，原因是什么？
5. 是否存在同名字段覆盖/遮蔽风险？

## 已实现能力

`field` 查询新增 `analysis`：

- `kind`: `local / related / computed / delegated / delegated_related`
- `declared_on_model`: 是否当前模型直接声明
- `storage`: `stored / non-stored`
- `related_path`: 规范化后的 related 路径
- `source_field`: 沿 depends/related 链追踪到的最终有效来源字段
- `writable` / `writable_reason`: 是否可写及原因
- `delegation_chain`: `_inherits` 逐跳链路，包含 `via_field`、`path`、`source_field`
- `shadowing`: 同名 delegated parent field 的覆盖/遮蔽风险

`model` 查询新增：

- `delegation_chain`: 模型级完整 `_inherits` 链，支持链式委托展示

human 输出会直接展示这些诊断信息；json 输出会保留结构化 `analysis`，便于脚本或 AI 消费。

```text

declared here : False
storage       : non-stored

flags         : compute=_compute_related, related=invite_id.vat, inverse=_inverse_related

  ifs.gar.entry.supplier.vat --invite_id (_inherits, path: invite_id.vat)--> ifs.gar.invite.supplier.vat
  ifs.gar.invite.supplier.vat --ifs_company_id (_inherits, path: ifs_company_id.vat)--> ifs.base.company.vat

shadowing risk: watch - field is resolved through same-name delegated parent field(s)
```

## 文档与技能更新

- README 增加 `_inherits` 委托字段诊断说明和示例。
- 仓库内 `odoo-graph-runtime-probe` skill 增加委托字段诊断规则：
  - 不只看 SQL 表结构或源码静态 grep。
  - 优先跑 `field` 读取 `analysis`。
  - 再跑 `model` 确认完整 `_inherits` 链。
  - 必要时跑 `path` 做最终来源字段证明。

## 后续改进候选

- 显示最终来源字段所属模块，例如 `effective origin module`。
- 区分“当前模型字段是否 stored”和“最终物理存储表/字段”。
- 对同名字段 shadowing 做更细分的级别：`none / watch / high` 之外，可加入 `shadowed`。
- 将 README 中较长的诊断说明拆分到独立文档，例如 `docs/field-diagnostics.md`。
