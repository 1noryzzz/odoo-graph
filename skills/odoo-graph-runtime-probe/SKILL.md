# odoo-graph-runtime-probe

## Runtime invariants

- 查询读取特定环境、特定时点导出的 registry 快照，不是实时业务数据。说明使用的 DB 与快照来源；不能用旧图证明当前源码或部署已生效。
- registry 可见字段不等于当前模型 SQL 表的物理列，尤其是 `_inherits`、related 和非存储字段。具体 SQL 仍须在目标 DB 核实物理表列。
- 图内依赖与 MRO 不证明 Python 实际调用、`super()` 执行、HTTP 路由生效或业务成功；这些结论需要相应源码或运行态证据。
- 区分关系为空、目标缺失和缓存无效。无路径仅说明当前图与查询条件下未找到路径，不能扩大为业务不可达。
- 部分命中仍可用，逐项标明缺失目标；不要因一个缺失项丢弃其他证据。

## 目标环境与缓存

- 从用户请求及上下文确定目标 DB；无法唯一确定时才询问，可列出缓存候选辅助选择。无需每次展示所有缓存或重复确认已知 DB。
- 优先复用匹配的缓存，核对 `meta.json` 的 `generated_at`、`odoo_path`、`cwd`、`package_version` 及已知源码、模块安装/升级变化。元数据不能单独保证新鲜度；来源或时效不足时明确限制。
- 离线查询不要求启动 Odoo。只有缓存缺失、不适合本次问题或用户要求刷新时才考虑 dump。
- dump 会启动 Odoo 环境并写出缓存。运行前核实配置、目标环境及初始化副作用；在已有授权覆盖且风险明确的环境中继续，不重复请求确认。若需要未授权的数据变更、服务操作或无法判断的生产影响，先澄清相关操作。
- 不为生成图擅自安装/升级模块、修改数据库或重启服务。环境不可用时继续可完成的源码调查，明确 registry 证据缺口。

## 查询选择与停止条件

按问题选择所需命令，不默认执行整套命令：字段来源用 `field`，模型结构用 `model`，模块贡献用 `module`，相关模型探索用 `context`，依赖影响用 `impact`，图内路径用 `path`，方法 MRO 用 `overrides`。

已知多个字段或方法时优先对应 batch 查询，避免重复加载图。得到支持结论的证据后停止；仅在缺失目标、失败或未解决疑点需要时追加查询。普通业务调查不运行 telemetry report。
